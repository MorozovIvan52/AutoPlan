## 📦 Что реализовано

### 1️⃣ Управление подписками (Billing)

```
├─ Три тарифа:
│  ├─ Start: 3 пользователя, 3 канала, 5 GB
│  ├─ Business: 25 пользователей, 10 каналов, 20 GB
│  └─ Enterprise: 100 пользователей, 20 каналов, 100 GB
│
├─ Автоматическое управление подписками:
│  ├─ Пробный период (14 дней)
│  ├─ Автоматическое продление
│  ├─ Автоматические повторные попытки платежа
│  ├─ Отмена подписки (прерывистое или немедленное)
│  └─ Upgrade/Downgrade (пересчёт платежей)
│
├─ Интеграция со Stripe:
│  ├─ Создание подписок
│  ├─ Обработка платежей
│  ├─ Управление платёжными методами
│  ├─ Webhook обработка (20+ event типов)
│  └─ Customer Portal (управление картой)
│
└─ История платежей:
   ├─ Счёта (invoices)
   ├─ Платежи с метаданными
   ├─ Экспорт в PDF
   └─ Email уведомления
```

Цены: сопоставимы с STOCRM (+10%). Рекомендация:

- **Start:** 899 ₽ / пользователь / месяц
- **Business:** 1,356 ₽ / пользователь / месяц
- **Enterprise:** 1,356 ₽ / пользователь / месяц (корпоративные условия — по запросу)

Первые 14 дней бесплатны (trial по умолчанию).

### 2️⃣ Контроль лимитов

```
├─ Четыре уровня лимитов:
│  ├─ Пользователи (3/25/100)
│  ├─ Каналы (3/10/20)
│  ├─ Хранилище (5/20/100 GB)
│  └─ API вызовы (100/1000/10000 в день)
│
├─ Enforcement (проверка на API уровне):
│  ├─ Создание пользователя — 403 если превышен лимит
│  ├─ Подключение канала — 403 если превышен лимит
│  ├─ Загрузка файла — 413 если недостаточно хранилища
│  └─ API вызовы — 429 если превышен rate limit
│
├─ Отображение в UI:
│  ├─ QuotaWarning компонент (показывает все лимиты)
│  ├─ QuotaPrecheck компонент (в формах создания)
│  ├─ BillingPage (детальный просмотр)
│  └─ Визуализация процентов (прогресс-бары)
│
└─ Оповещения:
   ├─ 🟢 < 80% — в норме
   ├─ 🟡 80-99% — предупреждение
   ├─ 🔴 100%+ — критическое, блокировка
   └─ Email alerts перед срезом лимита
```

## 🏗️ Архитектура системы

### Database Schema (Расширения)

```sql
-- Новые таблицы в БД:

-- Управление тарифами
subscription_plans        -- Определение тарифов (Start/Business/Enterprise)
tenant_subscriptions      -- Текущая подписка каждого тенанта
invoices                  -- История счётов

-- Отслеживание использования

-- Аудит и безопасность
audit_logs                -- Логирование действий администраторов

webhook_logs              -- История вызовов webhooks

-- Поддержка
support_tickets           -- Tickets для техподдержки
ticket_replies            -- Ответы на tickets
```

```
Admin Billing:
  GET  /admin/billing/subscription      — Текущая подписка

  GET  /admin/clients                   — Список клиентов

  GET  /admin/clients/audit-log         — История действий

Webhooks:
  POST /webhooks/stripe                 — Обработка платежей
```

## 🚀 Deployment

### Что нужно сделать перед запуском на production

1. **Stripe интеграция** (30 мин)
   - Создать аккаунт на stripe.com
   - Получить API ключи (Live mode)
   - Установить webhook
   - Синхронизировать тарифы

2. **База данных** (15 мин)
   - Добавить расширение schema
   - Запустить миграции (`npm run setup:prod`)
   - Проверить что таблицы созданы

3. **Окружение** (10 мин)
   - Добавить STRIPE_* переменные в `.env`
   - Добавить email сервис (SendGrid/SMTP)
   - Убедиться что HTTPS включен

4. **Тестирование** (30 мин)
   - Тест регистрации новой компании
   - Тест upgrade тарифа
   - Тест превышения лимита
   - Тест платежа

5. **Запуск** (15 мин)
   - `npm run build` — собрать фронтенд
   - `npm run setup:prod` — миграции
   - `pm2 restart crm` — перезагрузить приложение
   - Проверить http://domain.com/admin/billing

**Итого время:** ~2 часа от регистрации Stripe до запуска

## 📊 Метрики успеха

Когда проект запущен, отслеживайте:

- **MRR (Monthly Recurring Revenue)** — Ежемесячный доход
- **ARR (Annual Recurring Revenue)** — Годовой доход
- **Churn Rate** — % отмен подписок в месяц
- **LTV (Lifetime Value)** — Средний доход от клиента
- **CAC (Customer Acquisition Cost)** — Стоимость привлечения
- **NPS (Net Promoter Score)** — Готовность рекомендовать
- **Support Response Time** — Скорость ответа поддержки

**Целевые значения для B2B SaaS:**
- Churn Rate: < 5% в месяц
- NPS: > 40
- Support Response: < 24 часа
