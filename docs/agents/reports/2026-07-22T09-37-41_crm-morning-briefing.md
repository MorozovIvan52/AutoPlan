## 1. Что я вижу по коду (логика узлов)

| Узел | Назначение | Что отдаёт сканеру |
|---|---|---|
| `api/lib/ai-scanners.ts` | Реестр сканеров (incoming, deals, appointments, stock, tasks) — функции-детекторы аномалий | Списки id + причина (`reason`) для каждого раздела |
| `api/lib/chat-sla.ts` | SLA по чатам: окно первого ответа, эскалация, признак «просрочен» | Флаг `sla_breached` + `age_minutes` |
| `api/routes/tasks.ts` | CRUD задач + фильтр `due_at < now() AND status != 'done'` | Массив просроченных задач с `assignee_id` |

**Логика отбора по разделам брифинга:**

- **Входящие без ответа** — `chat_sla` где `last_inbound_at > last_outbound_at` ИЛИ `last_outbound_at IS NULL`, плюс `sla_breached = true`. Возраст считается в `chat-sla.ts` от `last_inbound_at`.
- **ЗН без обновления > 48 ч** — `service_deals` где `status IN ('open','in_progress')` И `updated_at < now() - interval '48 hours'`.
- **Записи на сегодня** — `service_appointments` где `scheduled_at::date = current_date`.
- **Нулевые остатки + активные ЗН** — JOIN `inventory` (qty ≤ 0) ↔ `service_deal_parts` ↔ `service_deals` (status активен).
- **Просроченные задачи** — `tasks` где `due_at < now()` и `status NOT IN ('done','cancelled')` — роут `GET /tasks/overdue` или эквивалент в `routes/tasks.ts`.
