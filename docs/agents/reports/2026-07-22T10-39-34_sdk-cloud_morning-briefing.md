## Срочно

| Что | Кому | Действие |
|-----|------|----------|
| **Входящие без ответа** — открытый диалог (`status=open`), последнее **реальное** сообщение от клиента (не системное Авито), **непрочитанное** (`unreadCount > 0`); SLA: предупреждение с **15 мин**, критично с **60 мин** (`chat-sla.ts`). Прочитали, но не ответили — в «Срочно» **не попадает**. | Менеджер / оператор на канале (или назначенный `assignedTo`) | Открыть **/** (входящие) → диалоги с бейджем времени ожидания. Ответить или передать коллеге. Приоритет: 🔥 горячие лиды (покупка/ремонт, score ≥ 62 в `scanChatOpportunities`). |
| **Авито: заказ/оплата** — системное уведомление об оплате без активной сделки в CRM | Менеджер запчастей | Оформить сделку в CRM, связать с диалогом. |
| **ЗН без движения > 48 ч** — `deals` с `orderType=service`, открытые статусы (`new`, `quoted`, `in_progress`, `waiting_parts`, `on_lift`, `qc`, `ready`), `updatedAt` старше 2 суток | Приёмщик + ответственный мастер (`assignedTo`) | **/zn** → колонки «Приём» / «В цеху» → отфильтровать по дате обновления. Обновить статус, комментарий клиенту, при `waiting_parts` — статус заказа запчастей. |
| **Записи на сегодня** — `service_appointments` на календарный день, `status ≠ cancelled` | Приёмщик | **/repairs** или **/calendar** → слоты на сегодня. Статус `scheduled` → подтвердить (`confirmed`). Проверить телефон, пост, пробег, привязку к ЗН. |
| **Склад при активных ЗН** — `parts_stock`: `qty ≤ minQty` (часто `qty=0`); в ЗН `in_progress` позиция упоминается в `description` или в строках заказа; резерв: `qty − reserved_qty` (`stock-reserve.ts`) | Менеджер склада / приёмщик | **/warehouse** → позиции ниже минимума. В карточке ЗН — резерв или заказ у поставщика; при нуле — согласовать срок/аналог с клиентом. |
| **Просроченные задачи** — `tasks`: `dueAt < now`, статус `todo` / `in_progress` | Исполнитель (`assignedTo`) | **/tasks** → фильтр просроченных; API: `GET /api/tasks/overdue-summary`. Закрыть или перенести срок с комментарием. |

**Где быстро собрать живую картину на проде:**  
`GET /api/analytics/today` — `urgentChats`, `tasksDueToday`, SLA-счётчики; `POST /api/ai/scan` — предложения по inbox/deal/repair/parts.

## Рекомендация: зайти в `/assistant` и нажать «Сканировать»

Встроенный сканер (`POST /api/ai/scan` → `runAllScanners` в `ai-scanners.ts`) создаст карточки в `ai_proposals`:

| Сканер | Что найдёт |
|--------|------------|
| **inbox** | Чаты за сегодня (МСК) с score ≥ 35: «Ждёт ответа», запрос на покупку, запись на ремонт, Авито |
| **deal** | КП (`quoted`) и заказы `in_progress` без обновления 2+ дня — follow-up клиенту |
| **repair** | Записи **на завтра** со статусом `scheduled` — подтверждение (не сегодняшние) |
| **parts** | Дефицит склада (`qty ≤ minQty`) при активном `in_progress` ЗН |
| **delivery** | СДЭК с треком — уведомление клиенту |

**Порядок:** `/assistant` → «Сканировать» → просмотреть pending → отредактировать текст → одобрить отправку в чат.  
Если proposals пустые — в CRM нет срабатываний по критериям (или нет данных в БД); сверка вручную по таблице «Срочно» выше.

### Справка по логике (из кода)

- **Входящие:** `needsManagerResponse` — клиент написал последним; срочность только при **непрочитанном** и ≥ 15 мин (`getChatSla`).
- **ЗН 48 ч:** порог `updatedAt < now − 48 ч`; открытые service-статусы — в `master-work.ts` (`OPEN_STATUSES`).
- **Записи сегодня:** `owner-dashboard.ts` — appointments в границах дня; UI — `/repairs`, API — `/api/service/appointments?from=&to=`.
- **Склад:** `scanPartsStage` — `qty ≤ minQty` + совпадение артикула с активным ЗН; резерв — `stock-reserve.ts`.
- **Задачи:** `GET /api/tasks/overdue-summary` — просрочка по текущему пользователю; фоновые напоминания — `task-reminders.ts`.
