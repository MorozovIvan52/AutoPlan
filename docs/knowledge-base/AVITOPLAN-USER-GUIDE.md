# CRM АвтоПлан — руководство пользователя и администратора

## Что это

**CRM АвтоПлан** — облачная CRM для автосервисов и магазинов запчастей: входящие (Авито, мессенджеры), клиенты, заказы, заказ-наряды, склад, доставка, отчёты.

Официальный сайт: [https://crmavito.online](https://crmavito.online)

---

## Как войти

1. Откройте адрес вашей организации:
   - **Основной сервер:** `https://crmavito.online`
   - **Отдельная компания (поддомен):** `https://ваша-компания.crmavito.online`
2. Введите email и пароль, выданные администратором.
3. Кнопка **«Демо-доступ»** — ознакомительный режим без реальных чатов (только для просмотра).

Если у вас несколько компаний, входите именно на домен своей компании. Один и тот же сотрудник не должен работать из чужого поддомена.

---

## Роли

| Роль | Возможности |
|------|-------------|
| **Администратор** | Всё + пользователи, настройки, интеграции, отчёты |
| **Оператор / менеджер** | Чаты, клиенты, заказы, ЗН, склад |
| **Демо** | Только просмотр тестовых данных |

## Ежедневная работа (кратко)

### Входящие сообщения
Раздел **«Входящие»** — все диалоги Авито, WhatsApp, Telegram в одном окне. Ответьте клиенту, назначьте диалог себе или коллеге.

### Клиент
**Клиенты** → карточка: телефон, VIN, авто, история заказов и чатов.

### Заказ запчастей
**Заказы** → новый заказ → привязать клиента → позиции со склада или под заказ.

### Заказ-наряд (СТО)
**ЗН** → создать наряд → VIN / госномер → работы из каталога → запчасти → печать.

### Склад
**Склад** — остатки, приход, резерв под ЗН.

### Настройки (админ)
**Настройки** → каналы Авито/Telegram, реквизиты для печати, телефония, ZZap.

## Несколько компаний — раздельные данные (SaaS)

Каждая **организация (тенант)** — отдельный «сейф» данных. Клиенты, заказы, чаты и склад одной СТО **не видны** другой.

### Вариант 1. Одна компания на основном домене (сейчас)

Для **crmavito.online** все данные в организации **«АвтоПлан»** (tenant по умолчанию). Подходит для одного автосервиса на одном сервере.

### Вариант 2. Новая компания через регистрацию (SaaS)

Администратор платформы создаёт организацию через API:

```http
POST https://crmavito.online/api/tenants/register
Content-Type: application/json
X-Register-Key: <TENANT_REGISTER_SECRET>

{
  "companyName": "СТО Мотор",
  "subdomain": "motor",
  "adminName": "Иван",
  "adminEmail": "admin@motor-sto.ru",
  "adminPassword": "НадёжныйПароль123"
}
```

После регистрации:
- Организация получает **trial 14 дней**
- Админ входит по `admin@motor-sto.ru`
- Рекомендуемый URL: **`https://motor.crmavito.online`** (нужен wildcard DNS `*.crmavito.online`)

### Пошагово для новичка: как создать вторую компанию

1. Придумайте отдельное название компании, например `СТО Мотор`.
2. Придумайте уникальный поддомен, например `motor`.
3. Создайте отдельный email администратора этой компании.
4. Отправьте запрос на `POST /api/tenants/register`.
5. После ответа откройте `https://motor.crmavito.online`.
6. Войдите под новым администратором.
7. Создайте сотрудников уже внутри этой компании.
8. Проверьте изоляцию:
   - в новой компании нет старых клиентов,
   - нет чужих заказов,
   - нет чужих чатов,
   - склад пустой или содержит только данные этой компании.

### Как понять, что данные действительно раздельные

- У каждой компании свой `tenant_id`
- Пользователь привязан к одной компании
- API фильтрует записи по `tenant_id`
- Поддомен автоматически выбирает нужную компанию
- После входа на `motor.crmavito.online` нельзя увидеть данные `crmavito.online`, если это другой tenant

### Вариант 3. Несколько пользователей в одной компании

Администратор организации:
1. **Настройки** → **Пользователи** (или раздел **Команда**)
2. **Добавить пользователя** — email, имя, роль (админ / оператор)
3. Сотрудник входит на **тот же домен**, что и компания

Все пользователи одной организации видят **общие** клиенты и заказы. Данные **других** организаций им недоступны.

## Безопасность данных (что защищает вас)

| Механизм | Что делает |
|----------|------------|
| **tenant_id** | Каждая строка в БД помечена организацией |
| **Фильтр в API** | Запросы отдают только данные вашего tenant |
| **Проверка при входе** | Пользователь привязан к организации; чужой поддомен не откроет ваши данные |
| **HTTPS** | Шифрование трафика |
| **Сессии** | Cookie httpOnly, срок 7 дней |
| **Демо-режим** | Изолированные тестовые данные, без записи |
| **Rate limit** | Защита от перебора паролей и флуда вебхуков |

**Важно для администратора:**
- Задайте сильные пароли (мин. 10 символов, буква + цифра)
- Не передавайте `TENANT_REGISTER_SECRET` и ключи Авито посторонним
- Отзывайте доступ уволенным сотрудникам (деактивация в пользователях)
- Делайте бэкапы БД (см. `docs/ops/BACKUP-S3.md`)

## Поддомены (для нескольких клиентов SaaS)

1. DNS: `*.crmavito.online` → IP сервера
2. SSL: wildcard-сертификат на nginx
3. В `.env` сервера: `TENANT_BASE_DOMAIN=crmavito.online`
4. При регистрации указывайте уникальный `subdomain`

Клиент заходит только на свой поддомен — контекст организации определяется автоматически.

---

## Метрики внедрения (для руководителя СТО)

Администратор может открыть:

`GET /api/tenants/adoption?days=7`

Показывает **Adoption Rate** — долю сотрудников с ≥3 целевыми действиями за неделю (заказы, VIN, сообщения).

## Поддержка и выход

- Выгрузка данных: администратор платформы — дамп PostgreSQL/SQLite по `tenant_id`
- При отмене подписки статус `expired` — чтение может остаться, изменения блокируются (настраивается)

## Частые вопросы

**Можно ли два автосервиса на одном логине?**  
Нет. Один email = одна организация. Для второй СТО — отдельная регистрация или отдельный пользователь внутри той же организации (филиалы — через «Предприятия СТО» в ЗН).

**Увидит ли конкурент наши заказы?**  
Нет, при корректной настройке tenant и поддоменов API не отдаёт чужие `tenant_id`.

**Где хранятся данные?**  
На сервере в РФ (VPS + SQLite/PostgreSQL). Для 152-ФЗ при масштабировании — managed PostgreSQL в российском облаке.
